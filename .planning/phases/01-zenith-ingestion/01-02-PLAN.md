<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| Zenith HTML body → Parser | Untrusted HTML with nested tables; cheerio parsing is server-side only |
| Description narration → Sender extractor | Narration is free-text; mis-attribution would corrupt downstream matching phases |
| Parsed fields → Validator | Validation is last gate before financial ledger write |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | src/zenith/parser.ts | high | mitigate | Per-field cheerio extraction not monolithic regex on raw HTML; regex applied to trimmed cell values only; truncated/missing rows return ParseFailure not partial object per T-1.9 |
| T-02-02 | Spoofing | src/zenith/sender.ts | high | mitigate | Family-specific extraction rules from spec; UNKNOWN family never guesses sender, stores raw description and flags for review per D-10 lenient-safe policy, preventing mis-attribution of funds |
| T-02-03 | Tampering | src/zenith/validation.ts | critical | mitigate | amount comma-strip + numeric >0 check + 2-decimal enforcement; date parsed via date-fns DD/MM/YYYY not new Date(); currency enum; future-date tolerance 5 min; Zod errors block insert |
| T-02-04 | Information Disclosure | src/db/transactions.ts | medium | mitigate | raw_email capped 100KB and CID images stripped per D-17; masked account stored as-is per D-08 never de-masked; attachments dropped |
| T-02-05 | Denial of Service | src/zenith/decode.ts | medium | mitigate | Strict decode throws on malformed B64/QP per D-09 so corrupt emails alert instead of retry-looping; caller handles as validation_failed not crash |
| T-02-SC | Tampering | npm installs | high | mitigate | Same audit as 01-01: pinned versions, no postinstall scripts; cheerio@1.2.0 and zod@4.5.4 already approved |
</threat_model>
