## Accomplishments

- Extended env validation with TELEGRAM_BOT_TOKEN, TELEGRAM_WEBHOOK_SECRET (1-256 A-Za-z0-9_-), TELEGRAM_ADMIN_CHAT_IDS, TELEGRAM_WEBHOOK_URL/PATH with safe defaults and fallback to TELEGRAM_CHAT_ID
- Implemented RingBuffer(500) with level-aware tail and wired as second pino destination via pino.multistream + Writable, preserving Railway JSON stdout and redacting secrets
- Built trust boundary: timingSafeEqual secret header check, numeric allowlist fail-closed, sliding-window rate limit (global 15/10s, poll 1/30s, watch 1/60s), and resilient sendMessage (escapeHtml, 4000 cap, 429 retry_after, 400 parse fallback, never throw)
- Delivered 7 commands (/help, /status, /health, /history, /suspicious, /logs, /poll, /watch) with DB timeouts, HTML escaping, 4096 truncation, and off-path triggers
- Extended worker http server with POST /telegram/webhook (403 on bad token, 200+warn on allowlist miss, global rate limit) and boot-time setWebhook + getWebhookInfo gated by env

## Decisions Made

- Zero new deps per RESEARCH recommendation — bare fetch for Bot API and crypto.timingSafeEqual for header verify
- Reuse existing node:http server on Railway PORT rather than adding express to avoid EADDRINUSE and keep worker single-process
- In-memory ring buffer as primary /logs source because RAILWAY_TOKEN not available in worker — Railway GraphQL not fetched without token
- Async off-path poll/watch via setImmediate with optimistic ack and follow-up sendMessage to avoid webhook timeout/retry duplicates
- Per-chat sliding windows (global 15/10s, poll 1/30s, watch 1/60s) to protect Gmail quota per Pitfall 8
